======================================================================
1. OBJETIVO DO PROJETO
======================================================================

Construir uma ferramenta confiavel para pesquisar uma debenture por:

- Codigo do ativo
- ISIN
- Nome ou CNPJ do emissor

A ferramenta devera montar uma ficha unica do ativo, consolidando dados de
fontes diferentes e exibindo a origem de cada informacao.

Principios do projeto:

- Nao inventar nem estimar dados ausentes.
- Preservar o historico dos valores.
- Registrar a fonte e a data de cada informacao.
- Nao sobrescrever silenciosamente dados validos.
- Manter o sistema funcionando quando uma fonte estiver indisponivel.
- Rejeitar duplicidades e dados inconsistentes.
- Registrar alteracoes manuais em auditoria.

4. TABELAS CRIADAS
======================================================================

4.1. schema_migrations

Controla a versao do esquema do banco e quais migrations ja foram
aplicadas.

4.2. issuers

Armazena os emissores das debentures.

Campos principais:

- ID interno
- CNPJ
- Razao social
- Nome fantasia
- Data de criacao
- Data de atualizacao

Protecoes:

- CNPJ unico.
- CNPJ com 14 digitos quando informado.
- Razao social obrigatoria.

4.3. debentures

Armazena a identidade de cada debenture.

Campos principais:

- ID interno
- Emissor
- Codigo do ativo
- ISIN
- Numero da emissao
- Serie
- Status
- Data de criacao
- Data de atualizacao
- Data de inativacao

Protecoes:

- Codigo do ativo unico.
- ISIN unico.
- Obrigatoriedade de codigo ou ISIN.
- Codigo armazenado em maiusculas.
- ISIN com 12 caracteres.
- Status limitado aos valores permitidos.
- Relacao com emissor protegida por foreign key.

4.4. sources

Armazena as fontes de dados e suas prioridades.

Fontes iniciais:

- SND
- CVM
- ANBIMA_API
- MANUAL

4.5. collection_runs

Registra cada execucao de coleta.

Informacoes previstas:

- Fonte utilizada
- Inicio e fim
- Status
- Quantidade solicitada
- Quantidade processada
- Quantidade com falha
- Resumo de erros

4.6. raw_records

Armazena as respostas brutas recebidas das fontes antes do parsing.

Informacoes previstas:

- URL consultada
- Parametros
- Conteudo HTML ou JSON
- Hash SHA-256
- Status HTTP
- Versao do parser
- Status do processamento
- Erro de processamento

Objetivo:

Permitir reprocessar os dados sem consultar novamente a fonte externa.

4.7. observations

Armazena os valores historicos de cada campo da debenture.

Exemplos de campos:

- Rating
- Spread
- Indexador
- Valor nominal
- Quantidade emitida
- Quantidade em mercado
- Vencimento

Cada observacao guarda:

- Debenture
- Fonte
- Campo
- Tipo do valor
- Valor
- Unidade
- Data observada
- Data coletada
- Nivel de confianca
- Checksum contra duplicidade

4.8. data_conflicts

Registra divergencias entre fontes sem apagar nenhum dos valores.

4.9. audit_log

Registra alteracoes manuais e administrativas.

Informacoes previstas:

- Usuario ou processo responsavel
- Acao
- Entidade alterada
- Valor anterior
- Valor novo
- Motivo
- Data e hora

4.10. current_observations

View que seleciona o valor consolidado atual de cada campo, considerando:

- Prioridade da fonte
- Data observada
- Data coletada
- Registro mais recente
